This document describes the attention backends available in sglang diffusion (sglang.multimodal_gen) and how to select them.

Overview

Attention backends are defined by AttentionBackendEnum (sglang.multimodal_gen.runtime.platforms.interface.AttentionBackendEnum) and selected via the CLI flag --attention-backend. Backend selection is performed by the shared attention layers (e.g. LocalAttention / USPAttention / UlyssesAttention in sglang.multimodal_gen.runtime.layers.attention.layer). --attention-backend is strict for the diffusion transformer / DiT. Auxiliary components such as encoders and VAEs use it when compatible, then fall back to a component default or a platform-compatible backend. Use --component-attention-backends when an auxiliary component must use a specific backend; incompatible overrides, including an override for a component that constructs no SGLang attention layer, fail unless a sparse backend is being replaced for cross-attention. A component key may carry a .self or .cross role suffix to override just one kind of attention; see Per-role overrides. When using the diffusers backend, --attention-backend is passed through to diffusers’ set_attention_backend (e.g., flash, _flash_3_hub, sage, xformers, native).
  • CUDA: prefers FlashAttention (FA3/FA4) when supported; otherwise falls back to PyTorch SDPA. On SM100/SM103 (B200/B300), dense non-causal fp16/bf16 native attention prefers cuDNN SDPA and falls back to FA4 if cuDNN has no compatible kernel.
  • ROCm: on Instinct (CDNA, gfx9) GPUs, defaults to aiter when --attention-backend is not set; on Radeon (RDNA) GPUs, use torch_sdpa. aiter_sage, aiter_quant and torch_sdpa can be selected explicitly. FlashAttention dispatches through FA3, which is CUDA-only, so fa falls back to PyTorch SDPA on ROCm.
  • Intel XPU: uses XPU Flash Attention backend (fp16/bf16, head sizes 64/96/128/192/256); otherwise falls back to PyTorch SDPA.
  • MUSA: uses FlashAttention when available; also supports Sage Attention when installed; otherwise falls back to PyTorch SDPA.
  • MPS: always uses PyTorch SDPA.
  • NPU: for ring attention uses FA otherwise uses PyTorch SDPA.
  • CPU: uses amx_attn when the CPU supports AMX, the dtype is bf16/fp16, and the head size is even; otherwise PyTorch SDPA.
On Blackwell, dynamic_cudnn_sdpa keeps FA4 for attention with one side shorter than 128 tokens and the other at least 128 during breakable CUDA graph warmup, capture and replay, including the eager breaks of a replay. In eager execution outside a graph, lossless and high requests use cuDNN for these shapes to avoid FA4 host-dispatch overhead; exact keeps the reference FA4 route. Switching backends can change floating-point rounding.

Selection priority

The selection order in runtime/layers/attention/selector.py is:
  1. global_force_attn_backend(...) / global_force_attn_backend_context_manager(...)
  2. Component and role override from --component-attention-backends.<component>.<role> while that component is being constructed
  3. Component override from --component-attention-backends while that component is being constructed
  4. CLI --attention-backend (ServerArgs.attention_backend)
  5. Layer or component default, when declared
  6. Auto selection (platform capability, dtype, and installed packages)
An explicit global backend mismatch fails for DiT self-attention. Auxiliary components may fall back to their declared default or another compatible backend. Sparse backends selected for self-attention similarly fall back to a compatible dense backend for cross-attention. Explicit component overrides are otherwise strict.

Per-role overrides

A role is the kind of attention a layer performs: self or cross. Appending a role to a component key selects a backend for just that role, which is useful when a quantized or otherwise expensive backend pays off for self-attention but not for the much lighter cross-attention:
Command 
sglang generate \
  --model-path <MODEL_PATH_OR_ID> \
  --component-attention-backends.transformer.self sage_attn \
  --component-attention-backends.transformer.cross fa
A role override outranks the component-wide backend for layers of that role and leaves the other role alone. Layers of a role with no override fall through to the component-wide backend as usual, and <component>_2 inherits <component>’s role overrides unless it declares its own. Role overrides are as strict as component-wide ones: a role override that never reaches a layer fails the load, including when the component builds no layers of that role at all. The one tolerated divergence is the shared sparse rule above — a sparse backend named for cross is replaced by a compatible dense backend and logged, rather than failing. Model and layer backend sets guide automatic selection; they are not positive allowlists for explicit requests. A backend selected with --attention-backend or --component-attention-backends can therefore be used without first adding it to every model’s set. It still fails closed when the platform cannot resolve it or when it lacks a required operation such as dense cross-attention, packed variable-length attention, or ring-attention LSE. Model paths that require one backend for correctness declare it as required; those layers keep that backend even when the surrounding component is overridden. For an automatic, measurement-based choice, pass --enable-attention-backend-autotune true. On each layer’s first sufficiently large input, the native runtime times compatible candidates and switches only when the output remains within its numerical guard and the measured gain exceeds the noise margin. The tuner is disabled by default and currently validated on SM90 and SM12x. It does not replace a backend selected explicitly through --attention-backend or --component-attention-backends, or a backend required by the model for correctness.

Configuration

Some backends require additional configuration. You can pass these parameters via --attention-backend-config. This argument accepts:
  • A path to a JSON or YAML configuration file.
  • A JSON string (e.g., '&#123;"sparsity": 0.5&#125;').
  • Key-value pairs (e.g., "sparsity=0.5,enable_x=true").
The key-value form splits on commas, so list values (for example Sol-Attn dense_layers=0,1 or VSA-H3 vsa_dense_layers) must use the JSON or file form, e.g. '&#123;"dense_layers": "0,1"&#125;' for Sol-Attn or '&#123;"vsa_dense_layers": [0, 1]&#125;' for VSA-H3 (a JSON list, not a string). Sol-Attn also accepts ranges such as dense_layers=0-1.

Usage

Select a backend via CLI

sglang generate \
  --model-path <MODEL_PATH_OR_ID> \
  --prompt "..." \
  --attention-backend fa
sglang generate \
  --model-path <MODEL_PATH_OR_ID> \
  --prompt "..." \
  --attention-backend torch_sdpa

Override one component

Use component overrides when a specific module needs different attention semantics from the main transformer: 
sglang generate \
  --model-path <MODEL_PATH_OR_ID> \
  --prompt "..." \
  --attention-backend fa \
  --component-attention-backends text_encoder=torch_sdpa
Component keys match pipeline module names from model_index.json, such as text_encoder, text_encoder_2, transformer, transformer_2, or connectors. Use this override when the fallback must be pinned: unlike the global backend, an incompatible component override raises an error instead of selecting another backend. The one role-based exception is a sparse self-attention backend, which uses a compatible dense backend for cross-attention layers in the same component. The component must construct SGLang-selectable attention or explicitly defer selection until first use; components with fixed attention reject the override. Per-component overrides apply only to native pipelines. The Diffusers backend accepts the global --attention-backend passthrough instead.

Per-request override (denoise loop)

A single server can serve exact and approximate attention side by side: requests may switch the DiT denoise attention backend via the attention_backend_override sampling param. Valid values are the exact/drop-in dense kernels — fa, torch_sdpa, sage_attn, sage_attn_3. The field participates in the dynamic-batch signature, so requests with different backends never share a batch. 
sglang generate \
  --model-path <MODEL_PATH_OR_ID> \
  --prompt "..." \
  --attention-backend-override sage_attn
client.images.generate(
    model="<MODEL_PATH_OR_ID>",
    prompt="...",
    extra_body={"attention_backend_override": "sage_attn"},
)
Incompatible server settings reject the request (with a server log) instead of silently falling back: breakable CUDA graphs and torch.compile bake the attention kernel into a captured/traced graph; sparse server backends (sliding_tile_attn, video_sparse_attn, …) cannot be mixed with per-request dense switching; under ring parallelism the target must be ring-capable. Note sage_attn / sage_attn_3 are lossy (quantized attention) — validate quality on your workload.

Request-scoped Skip Softmax

Skip Softmax (BLASST) keeps the QK matmul, but skips the exponential, softmax-state update, V load, and PV matmul for attention tiles whose estimated softmax mass is below a threshold. It is an explicit lossy optimization backed by the FlashInfer kernels shipped with SGLang’s pinned dependencies. See the BLASST paper and NVIDIA’s video-generation study for the algorithm and measured quality/performance trade-offs. Pass skip_softmax_params in one image or video request. The runtime routes compatible self-attention layers through the FA/FlashInfer path for that batch; cross-attention keeps its normal backend, and the next request restores the server default. 
client.videos.create(
    model="<MODEL_PATH_OR_ID>",
    prompt="...",
    extra_body={
        "skip_softmax_params": {
            "threshold_scale_factor": 500.0,
            "start_step": 14,
        }
    },
)
  • threshold_scale_factor is required and must be positive. The kernel uses threshold_scale_factor / context_length; larger values skip more work and usually increase quality loss.
  • start_step is the zero-based denoising step at which sparse execution starts. It defaults to 0; keeping early high-noise steps dense is generally safer.
There is intentionally no default threshold. Calibrate the threshold and start step against output-quality metrics for each model, resolution, step count, and deployment backend; values tuned for one workload are not portable. Current support is FP16/BF16, head dimension 128 or 256, and unmasked self-attention on Hopper SM90 and Blackwell SM100/SM103/SM107. Ulysses sequence parallelism is supported because the kernel runs after its all-to-all. Ring Attention, attention masks, torch.compile, and breakable CUDA graphs reject the request instead of silently running dense attention. Models that merely offer an FA backend do not automatically qualify: the runtime still checks the GPU, dtype, head dimension, attention role, and execution mode.

Using SpargeAttention

Install the optional CUDA extension, then select the backend explicitly: 
pip install ninja
pip install git+https://github.com/thu-ml/SpargeAttn.git --no-build-isolation

sglang generate \
  --model-path <MODEL_PATH_OR_ID> \
  --prompt "..." \
  --attention-backend sparge_attn \
  --attention-backend-config topk=0.5
sparge_attn applies to compatible self-attention layers. Cross-attention uses the existing dense fallback; short self-attention and asymmetric Q/KV also use dense SDPA. LTX-2, LTX-2.3, and LTX-2.5 have compatible video (128) and audio (64) head dimensions, so their sufficiently long, unmasked self-attention uses SpargeAttention while prompt and audio-video cross-attention remain dense. Ulysses sequence parallelism is supported, but ring attention is not because the upstream kernel does not expose the softmax LSE needed for ring merging. K/V-gather SP therefore follows the normal sparse-backend rule and uses Ulysses instead.

Sage then Sol hybrid

sol_attn keeps the first dense_steps steps dense. Set dense_backend=sage_attn to run that prefix on SageAttention and the tail on Sol sparse attention. Keep the text encoder on torch_sdpa: 
sglang generate \

Both sage_attn and sol_attn are approximate. The default DiT backend remains fa.

Ascend quantized attention with MindIE-SD

On Ascend NPU, fa can use the public mindiesd.quant_attention API for FP8, MXFP8, and MXFP4 attention. This integration targets MiniMax-H3; Wan/FLUX support is out of scope. Omitting precision preserves the existing native Ascend FA behavior, including its opt-in MXFP8 path. Set precision=bf16 to explicitly select native floating-point attention. Neither requires MindIE-SD. When FA is an internal dense fallback for another selected backend, that backend’s precision does not enable quantized FA. The denoising stage passes configuration through AscendFAMetadata; the FA constructor does not read global server arguments. Quantization applies to DiT self-attention. H3 refiners and cross-attention do not inherit its quantized path.

Configure attention

Parameter Type Description Default
precision str bf16 selects native floating-point FA; fp8, mxfp8, or mxfp4 selects MindIE-SD. Unset (existing native selection)
fp8_fa_mode str FP8 only; HIGH_PRECISION or C8V16_TILING512 (head dimension 128). HIGH_PRECISION
head_chunk_size int MHA heads per SD call. Use 0 to disable chunking, or another positive integer. 4
qk_rotation bool Apply online Q/K rotation before quantization. Not used by the native BF16 path. true, or false when the checkpoint already includes offline Q/K rotation
C8V16_TILING512 is an alternative FP8 compute/tiling mode for head dimension 128. It changes the V block layout and the fused kernel’s internal precision setting; Q/K/V still pass through SDK quantization. Compare its latency and numerical quality with HIGH_PRECISION on your workload before choosing it. See the SDK implementation. For example, run MiniMax-H3 on two NPUs with FP8 C8V16 and the default chunk size: 
sglang generate \
  --model-path /models/MiniMax-H3 \
  --model-variant fl2va \
  --performance-mode manual \
  --num-gpus 2 --tp-size 2 \
  --vae-config.use-parallel-tiling false \
  --attention-backend fa \
  --attention-backend-config '{"precision":"fp8","fp8_fa_mode":"C8V16_TILING512"}' \
  --prompt "A cat walking on a sunny beach, gentle waves." \
  --save-output
For MXFP8 or MXFP4, use '{"precision":"mxfp8"}' or '{"precision":"mxfp4"}'. Use '{"precision":"bf16"}' for a native floating-point attention baseline, even when native MXFP8 is enabled in the environment. The text encoder keeps its normal backend selection. Attention precision is independent of linear-weight quantization. Add --quantization mxfp8 only if online MXFP8 linear weights are also wanted. The SD path uses attention_backend_config; it does not need the native SGLANG_DIFFUSION_ENABLE_MXFP8_ATTENTION or SGLANG_DIFFUSION_MXFP8_FA_HEAD_CHUNK_SIZE variables. Head chunking applies to dense and packed MHA, including a smaller final chunk. GQA is delegated to the SDK without head chunking. Packed sequences remain isolated and H3 trailing padding is zeroed. Ordinary Ulysses is supported; causal attention, nonzero dropout, Ring attention, and softmax LSE are unsupported. Online rotation follows native Ascend FA’s deterministic rotation and is applied once by the SDK, before quantization. Checkpoints with offline Q/K rotation default to no online rotation; explicitly enabling both is rejected.
MindIE-SD 3.2.0 pads MXFP4 sequence lengths to multiples of 512. The padded K/V positions participate in softmax. SGLang preserves this SDK behavior; validate numerical quality with the sequence lengths used by your workload.

Using Sliding Tile Attention (STA)

STA_INFERENCE also reads the per-layer STA parameters from the file named by the SGLANG_DIFFUSION_ATTENTION_CONFIG environment variable. STA_SEARCHING writes one opaque sample name per submitted request; its positive and negative loss files share that name in separate directories. Repeating the same prompt adds a sample rather than overwriting the previous one. Existing calibration JSON remains readable. Use a private calibration directory; older files are not renamed or removed. 
# Pass the mask strategy file path via config
SGLANG_DIFFUSION_ATTENTION_CONFIG=/abs/path/to/sta_config.json \

  --prompt "..." \

Using Ascend Sparse Attention

Use a Linux Ascend environment with the prerequisites above. Set MODEL_PATH to a supported pipeline’s local directory or Hugging Face repository ID. This example uses one NPU with Ulysses degree 1, BF16 sparse attention, and the shared BF16 FA executor for the first 10 and final 2 steps: 
MODEL_PATH="/path/to/pipeline"
sglang generate \
  --model-path "${MODEL_PATH}" \
  --num-gpus 1 \
  --ulysses-degree 1 \
  --attention-backend ascend_sparse_attn \
  --attention-backend-config '{"sparse_type":"rf_v3","precision":"bf16","sparsity":0.6,"skip_first_steps":10,"skip_last_steps":2,"dense_kwargs":{"precision":"bf16"}}' \
  --prompt "A sailboat crossing a calm lake at sunrise"
For supported A5 operators, use "precision":"mix" for EagleQBSA sparse steps. To select FP8 dense attention independently, set "dense_kwargs":{"precision":"fp8","fp8_fa_mode":"HIGH_PRECISION"}. For MXFP4 dense attention, use "dense_kwargs":{"precision":"mxfp4"} and any supported MXFP4-specific options; omit FP8-specific options.

Notes for ROCm / MPS

  • ROCm: Instinct (CDNA, gfx9) GPUs default to aiter; use --attention-backend torch_sdpa on Radeon (RDNA) GPUs or when AITER is unavailable (fa also resolves to torch_sdpa on ROCm). On gfx1151 / Strix Halo (wave32), do not use aiter — prefer torch_sdpa (image sets SGLANG_USE_AITER=0).
  • MPS: the platform implementation always uses torch_sdpa.
